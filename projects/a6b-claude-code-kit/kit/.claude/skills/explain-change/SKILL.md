`$base`（省略時は `main`）との差分を読み、**技術者以外に説明できる形**にする。

## 手順

1. 差分の範囲を確認する

`$base` が空のときは `main` を使う。
**シェルの既定値展開（`${base:-main}`）は使わない** — 名前付き引数の置換と
シェルの展開が混ざり、どちらが効いているか分からなくなるため。
比較対象を決めてから、次を実行する。

```bash
git diff --stat <比較対象>...HEAD
```

2. 変更を「何が変わるか」の単位にまとめる

ファイル単位ではなく、**利用者から見た変化**の単位でまとめる。
ファイルを列挙しただけの説明は、引き継ぎに使えない。

## 出力の形式

```
## 何が変わるか
（利用者から見た変化。2〜4項目）

## なぜ必要だったか
（変更前に何が問題だったか）

## 影響範囲
（既存の動作が変わる箇所。無ければ「なし」と書く）

## 確認してほしいこと
（レビュー担当が実際に見るべき箇所・操作）
```

## 書くときの制約

- **「リファクタリング」「最適化」で済ませない。** 何がどう変わったかを書く
- 影響範囲が分からない場合は「**分からない**」と書く。推測で「影響なし」と書かない
- 設定ファイルの変更は、**他人の環境で何が起きるか**を必ず書く
