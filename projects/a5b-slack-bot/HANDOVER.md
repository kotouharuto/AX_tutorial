# 引き渡しドキュメント：問い合わせ振り分け Bot（Slack 版）

最終更新：2026-10-18
書き分けは A-3 と同じ。**【事実】** は実機で確認済み、**【要記入】** は組織ごとに決める空欄。

---

## 1. これは何をするものか

【事実】
Slack で `/inquiry 問い合わせ文` と送ると、AI（Gemini）が4つに分類し、担当チャンネルに通知します。
送った人には、分類の結果がその人にだけ見える形で返ります。

| 分類 | 通知先（`routing.json` で変更可） |
|---|---|
| システム障害 | `#inq-system` |
| 申請手続き・備品・設備 | `#inq-general` |
| その他 | `#inq-ops`（担当未設定として届く） |

失敗したとき（分類できない・通知できない・Slack との接続が切れて起動し直した）も `#inq-ops` に届きます。

## 2. 使い方

【事実】

| したいこと | 手順 |
|---|---|
| 問い合わせを送る | 任意のチャンネルで `/inquiry 問い合わせ文` |

| 分類の種類を変える | コードの変更が要る（`src/classifier.py`） |
| 止める・起動し直す | 8章 |

## 3. 動く条件

【事実】

| 条件 | 内容 |
|---|---|
| 動かす場所 | **常に電源が入り、ネットワークにつながったマシン。** 検証では macOS の launchd で常駐させた。マシンがスリープすると Bot も止まる |
| 公開 URL | 不要（Socket Mode：Bot から Slack に接続しに行く方式） |
| Slack のアプリ | **ワークスペースごとに1つ作る。** Socket Mode のアプリは Slack のマーケットプレイスに出せないため、使い回しはできない |
| 鍵 | 3つ（→ 7章） |
| 費用 | Gemini の API は**前払い**。残高が尽きると分類が止まる（→ 5章） |

【要記入】どのマシンで動かすか。そのマシンを誰が管理するか

## 4. 権限（スコープ）を追加するとき（重要）

【事実】
機能を足すと、Slack アプリの権限が足りなくなることがあります（例：チャンネルに投稿するには `chat:write`）。
**権限は、次の3段階をすべて終えるまで効きません。** 途中で止めても、エラーの見た目がほぼ変わらないので気づきにくいです。

| 段階 | 作業 | 終えていないときのエラー |
|---|---|---|
| 1 | `manifest.yaml` の `oauth_config.scopes.bot` に権限を足し、Slack のアプリ管理画面（https://api.slack.com/apps → 対象アプリ → App Manifest）に同じ内容を貼って保存する | `missing_scope` |
| 2 | **アプリをワークスペースに再インストールする**（管理画面の「Install App」）。権限の確認画面で、足した権限が載っていることを確かめて許可する | **`missing_scope`（段階1の前と同じ）** |
| 3 | 投稿先のチャンネルに Bot を招待する：そのチャンネルで `/invite @inquiry-bot` | `not_in_channel` |

### 落とし穴

- **マニフェストを保存しただけでは、権限は増えません。** マニフェストは「次にインストールするとき求める権限」の宣言にすぎません。
  段階1の前と後でエラーが同じ `missing_scope` なので、「足したのに直らない」に見えます。
- 見分け方：Bot は `#inq-ops` の通知とログに **「必要な権限」と「トークンの権限」** を出します。
  トークンの権限に足したものが無ければ、段階2が済んでいません。
- **エラーに出る権限の名前と、マニフェストに書く名前が違うことがあります。**
  検証では、エラーは `chat:write:bot` を求めましたが、マニフェストに書いて効いたのは `chat:write` でした。
  エラーの名前をそのまま貼らず、Slack の権限一覧で正しい名前を確かめてください。
- 再インストールしても、**Bot のトークン（`xoxb-`）の文字列は変わりませんでした**（検証時）。`.env` の書き換えは不要でした。
  変わった場合は `.env` を書き換えて起動し直します。
- 再インストールは、ワークスペースの設定によっては**管理者の承認が要る**ことがあります（検証は自分が管理者のワークスペースで行ったため未確認）。

**チェック**：段階3の後、`/inquiry` を送り、通知先のチャンネルに届くこと。

【要記入】再インストールを承認できるのは誰か

## 5. うまくいかないとき

【事実】
まず `#inq-ops` を見ます。失敗の多くはそこに原因と直し方が出ます。

| 症状 | 原因 | 対処 |
|---|---|---|
| `#inq-ops` に「分類の失敗・HTTP 402」 | Gemini の前払い残高が無い・前払いへの切り替えが必要 | Google AI Studio で支払い設定を確認する |
| 「分類の失敗・HTTP 429」 | 利用上限（10分で10米ドル等） | 時間をおく。頻発するなら上限の引き上げを検討 |
| 「分類の失敗・HTTP 400」 | API キーの誤り・無効 | `.env` の `GEMINI_API_KEY` を確認する（→ 7章） |
| 「通知の失敗・`missing_scope`」 | 権限が足りない／再インストールしていない | 4章 |
| 「通知の失敗・`not_in_channel`」 | Bot が通知先のチャンネルにいない | そのチャンネルで `/invite @inquiry-bot` |
| 「通知の失敗・`channel_not_found`」 | `routing.json` のチャンネル ID が違う | ID を直して起動し直す |
| 利用者の画面に「アプリが応答しなかったため、/inquiry は失敗しました」 | **Bot が Slack とつながっていない**（停止中・マシンがスリープ・接続が壊れている） | 8章で状態を見る。Bot は5分つながらないと自分で終了し、自動で起動し直す |
| `#inq-ops` に「接続が◯秒切れたため Bot を終了し、起動し直しました」 | 上の自動復旧が働いた | 対処は不要。**その間に送られた問い合わせは受け付けられていない**ので、心当たりのある人に再送を頼む |

### 知っておくこと

- 「アプリが応答しなかった」は **Gemini や API の問題に見えますが、多くは接続の問題です。**
  検証では、プロセスは動いたまま Slack との接続だけが約7時間45分壊れ続けた例がありました。
  そのため Bot 自身が接続を見張り、**5分つながらなければ終了 → launchd が起動し直す**作りにしています。
- ネットワークが切れている間は、起動し直しても失敗し、**30秒ごとに起動と失敗を繰り返します。**
  ネットワークが戻れば自然に回復します（検証では Wi-Fi を戻して30秒以内に回復し、`#inq-ops` に通知が出た）。
- 利用者に「失敗しました」と出ても、`#inq-ops` に知らせられた場合は「もう一度送る必要はありません」と案内しています。
  **再送すると二重に通知されます。**

【要記入】`#inq-ops` を誰が見るか。その人が不在のときは誰が見るか

## 6. やってはいけないこと

【事実】

- **トークンや API キーを Slack・メール・チャットに貼らない。** 漏れたら Slack の管理画面で再発行する
- **`.env` をリポジトリに入れない**（`.gitignore` で除外済み）
- 業務で使っているワークスペースで、管理者の承認なしにアプリを入れない
- 問い合わせの本文は Gemini（Google の外部サービス）に送られる。**送ってはいけない情報が書かれうる窓口では使わない**

【要記入】この組織で扱ってはいけない情報

## 7. 鍵について

【事実】
`.env`（このフォルダ。コミットしない）に3つ入れます。手順は `SETUP.md`。

| キー | 中身 | 取得場所 |
|---|---|---|
| `SLACK_BOT_TOKEN` | `xoxb-` で始まる | アプリ管理画面「Install App」 |
| `SLACK_APP_TOKEN` | `xapp-` で始まる（`connections:write`） | 「Basic Information」→「App-Level Tokens」 |
| `GEMINI_API_KEY` | Gemini の API キー | Google AI Studio |

入れた後は、**値を表示せずに**検査できます：

```bash
uv run python src/settings.py
```

取り違え・空白の混入（全角スペースを含む）・キー名の打ち間違いを見つけます。

【要記入】Slack アプリと Gemini のキーを誰の名義で作るか。費用を誰が負担するか

## 8. 常駐のさせ方と止め方（macOS）

【事実】
`launchd/com.axtutorial.a5b-slack-bot.plist` を使います。中のパスは**このマシンの絶対パス**なので、
別のマシンでは書き換えが要ります。

```bash
# 登録（ログイン時にも自動で起動する）
cp launchd/com.axtutorial.a5b-slack-bot.plist ~/Library/LaunchAgents/
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.axtutorial.a5b-slack-bot.plist

# 状態（state = running なら動いている）
launchctl print gui/$(id -u)/com.axtutorial.a5b-slack-bot

# 起動し直す（routing.json や .env を変えたとき）
launchctl kickstart -k gui/$(id -u)/com.axtutorial.a5b-slack-bot

# 止めて、登録も外す
launchctl bootout gui/$(id -u)/com.axtutorial.a5b-slack-bot
```

ログは `output/launchd.err.log`（Bot の記録は標準エラー出力に出る）。

## 9. 引き継ぐとき

【事実】

- Slack アプリの管理者（コラボレーター）に後任を加える。作った人しか管理画面に入れない状態で退職すると、権限の追加（4章）ができなくなる（追加の手順は未検証）
- Gemini の API キーと支払いの名義を確認する（前払い残高が尽きると止まる）
- 常駐させているマシンを確認する。そのマシンが止まれば Bot も止まる

【要記入】後任者
