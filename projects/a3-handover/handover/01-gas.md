# 引き渡しドキュメント：問い合わせ自動振り分け（GAS 版）

最終更新：2026-09-23

---

## 1. これは何をするものか

【事実】
Google フォームに問い合わせが届くと、内容を AI が読んで4つに分類し、
担当者へメールで転送します。分類の結果はスプレッドシートに自動で記録されます。

分類：システム障害 / 申請手続き / 備品・設備 / その他
緊急度：高 / 中 / 低

---

## 2. 使い方

【事実】

| したいこと | 手順 |
|---|---|
| 問い合わせを受け付ける | 何もしなくて構いません。フォームが送信されると自動で動きます |
| 処理結果を見る | スプレッドシート「A1-workflow」の「回答」シートを開きます。右側5列（分類・緊急度・担当者・状態・詳細）に結果が入ります |
| 担当者を変更する | 同じスプレッドシートの「担当マスタ」シートで、分類に対応するメールアドレスを書き換えます。**保存するだけで次回から反映されます** |
| 失敗した問い合わせをやり直す | Apps Script の画面で `retryFailedRows` を実行します（→ 5章） |

## 5. うまくいかないとき

【事実】

| 症状 | 考えられる原因 | 対処 | 自分で直せるか |
|---|---|---|---|
| 問い合わせが来てもメールが届かない | AI の API キーが失効した | 「詳細」列を確認。401 と書かれていればキーの問題 | 連絡が必要 |
| 「状態」列が「エラー」になっている | AI の呼び出しに失敗 | 原因を直したあと `retryFailedRows` を実行 | 連絡が必要 |
| 「状態」列が「未分類」になっている | 担当マスタに宛先が設定されていない | 「担当マスタ」シートに担当者を追加 | **自分で直せます** |
| 何も起きない（列が空のまま） | シート名が変わった／トリガーが消えた | → 8章 | 連絡が必要 |

### エラー通知について

【事実】
処理に失敗すると、`FALLBACK_TO` に設定されたアドレスへ自動でメールが届きます。
件名：`[A1-workflow] 問い合わせの処理に失敗しました`

**この通知が届かない状態＝異常に気づけない状態**です。通知先が正しいか定期的に確認してください。

## 6. やってはいけないこと

【事実】

- **「回答」シートのシート名を変えない**。変えると仕組みが停止し、しかも通知も届きません（2026年9月に実際に起きました）
- **「回答」シートの列の順番を変えない・列を削除しない**
- **`setup` を何度も実行しない**（現在は対策済みですが、以前はフォームが増殖しました）
- **同じスプレッドシートを別の自動化ツールから同時に操作しない**。先に処理した方が勝ち、もう片方は「処理済み」と判断して何もしません

## 8. 引き継ぐとき（重要）

【事実】

所有権を移すだけでは**動きません**。以下が必要です。

| 対象 | 移管できるか | 対処 |
|---|---|---|
| スプレッドシート・フォーム | できる | Drive で所有権を移転。**共有ドライブに置くとより安全**（組織が所有するため） |
| スクリプト | できる（親ファイルに追従） | 上記と同時に移る |
| **トリガー（自動実行の設定）** | **できない** | 引き継ぐ人が Apps Script で `setup` を実行する |
| **承認（アカウントの許可）** | **できない** | 引き継ぐ人が自分で承認する |
| API キー | — | 引き継ぐ人の名義で取り直す |

**引き継ぎ作業は「所有権を移した」だけでは終わりません。**
見た目は成功しますが、トリガーが元の人のアカウントで動き続け、
そのアカウントが停止した時点で止まります。しかも**タイムラグがあるため、
引き継ぎから数週間〜数ヶ月後に、無関係な変更を疑いながら調査することになります**。

### 引き継ぎチェックリスト

```
□ スプレッドシートとフォームの所有権を移した
□ 引き継ぐ人が Apps Script を開けることを確認した
□ 引き継ぐ人が `setup` を実行し、トリガーを作り直した
□ 古い所有者のトリガーを削除した
□ API キーを引き継ぐ人の名義で設定し直した
□ FALLBACK_TO（エラー通知先）を引き継ぐ人のアドレスに変更した
□ フォームから1件送信して、動くことを確認した
```
