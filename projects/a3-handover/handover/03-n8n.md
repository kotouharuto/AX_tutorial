# 引き渡しドキュメント：問い合わせ自動振り分け（n8n 版）

最終更新：2026-09-23

---

## ⚠️ この仕組みは、現状では引き渡せません

【事実】

A-1 の GAS 版と同じ処理を n8n で組みましたが、**引き渡し可能な状態にはなりませんでした。**
理由を以下に記します。**「渡せないものの手順書」として残します。**

---

## 1. 引き渡せない理由

### 1-1. 7日で自動的に止まる

Google との連携（OAuth）が**テストモード**のため、**認証が7日で失効します。**
誰も何もしていないのに、1週間後に止まります。実際に 2026-09-21 頃に停止しました。

**本番モードにすれば無期限になりますが、Google の要件として
「公開されたホームページの URL」と「プライバシーポリシーの URL」が必要です。**
個人や小規模での検証では用意できません。

- 止まったことは通知されません（トリガー自体が動かないため、エラーも発生しない）
- 復旧にはブラウザで Google にサインインし直す必要があり、**そのアカウントの持ち主にしかできません**

### 1-2. 担当者をシートで管理できない

n8n は「前の処理が出したデータの件数だけ、次の処理を繰り返す」仕組みです。
担当マスタ（6行）を読むと、**以降の処理が6倍実行され、同じメールが6通送信されました。**

対策を試しましたが解決せず、最終的に**宛先をコードに直接書く**形にしました。

つまり **n8n 版では、担当者の変更にコードの修正が必要です。**
GAS 版はシートを書き換えるだけで済みます。

### 1-3. 即時ではない

フォームが送信されても、n8n は**最大1分後**に気づきます（1分ごとにシートを見に行く方式）。
GAS 版は送信の瞬間に動きます。

---

## 2. それでも n8n が向いている場面

【事実】

上記は「Google のサービス内で完結する処理」を n8n で組んだ場合の話です。
**外部のサービス（Slack、Notion、社内システムなど）を跨ぐ処理**なら、n8n の方が適しています。

| | GAS | n8n |
|---|---|---|
| Google 内で完結 | **向いている** | 向いていない |
| 外部 SaaS を跨ぐ | できない | **向いている** |
| 実行の様子を見る | ログ画面 | **各ステップの入出力が画面で見える（優れている）** |

## 3. 現在の構成（記録として）

【事実】

```
Google Sheets Trigger（1分ごと）
  → Filter（未処理の行のみ）
  → HTTP Request（Gemini で分類）
  → Code（パース・検証・宛先決定）
  → Gmail（振り分けメール）
  → Google Sheets Update（結果を記録）

別ワークフロー：Error Trigger → Gmail（失敗時の通知）
```

- アクセス先：`http://localhost:5678`
- 認証：Google Sheets / Google Sheets Trigger / Gmail の**3本**（それぞれ独立して失効します）
- API キー：Header Auth クレデンシャル（`x-goog-api-key`）

## 4. 動かし続けるために必要なこと

【事実】

もし運用するなら、以下が前提になります。

```
□ 独自ドメインと、公開されたホームページ・プライバシーポリシーを用意する
□ Google の OAuth 同意画面を本番モードで公開する
□ n8n を常時起動できるサーバに置く（現在は個人の Mac 上の Docker）
□ 担当者の変更が発生するたびに、コードを修正できる人を確保する
□ 3本の認証が切れていないかを定期的に確認する仕組みを作る
```

## 5. この記録の意味

【事実】

**「GUI ツールだから非エンジニアでも運用できる」は成り立ちませんでした。**

- 構築：GAS 約2時間 に対して n8n 約2日
- 担当者の変更：GAS はシート編集（誰でも可）、n8n はコード修正（技術者のみ）
- 停止リスク：GAS はなし、n8n は7日ごと

技術選定では「n8n の方が簡単そう」という印象が先に立ちますが、
**実際に組んで引き渡す段階まで持っていくと、評価が逆転しました。**
