# 引き渡しドキュメント：社内文書検索（Claude Project 版）

最終更新：2026-09-23

---

## 1. これは何をするものか

【事実】
社内の規程・手順書を Claude に読み込ませてあり、質問すると根拠付きで答えます。
回答は必ず次の形式で返ります。

```
【分類】カテゴリ / 緊急度
【回答】結論
【根拠】該当する記述の要約
【出典】文書名
【注意】矛盾・画像由来・未確認事項があれば記載
```

**回答案を作るところまでが役割です。そのまま返信せず、必ず人が確認してください。**

## 3. 回答の読み方（重要）

【事実】

| 回答 | 意味 | 次にすること |
|---|---|---|
| 【出典】に文書名がある | その文書に根拠がある | 【根拠】が質問に答えているか確認 |
| 「読み込んだ文書内には、該当の記述が見つかりませんでした」 | 文書に書かれていない | 担当部署に確認する。**AI が知らないだけで、社内にルールがある可能性があります** |
| 【注意】に「文書間で記載が異なる」 | 古い文書と新しい文書が矛盾している | **管理部門に確認が必要**。どちらかを選んで回答しないこと |
| 【注意】に「画像由来のため要確認」 | スキャンした PDF から読み取った情報 | 元の文書を目視で確認する |

**【出典】が空の回答は使わないでください。** 根拠なしに答えている可能性があります。

## 4. 文書を追加・更新したいとき

【事実】

手順そのものは簡単です。

1. プロジェクトを開く → 右の「プロジェクトナレッジ」
2. 追加：「＋」からファイルを選ぶ
3. 更新：古いファイルを削除してから、新しいファイルを追加

**難しいのは手順ではなく、何を入れるかの判断です。**

### 投入前チェックリスト

```
□ このプロジェクトを使う人全員が見てよい文書か
  （見せてはいけない文書は、そもそも入れない。指示で制限しても引き出されます）
□ 同じ規程の古い版がナレッジに残っていないか
  → 残っていると「文書によって記載が異なります」という回答が増えます（実測：8問中5問）
□ 新しい部署名・システム名・略語が含まれていないか
  → あれば用語集（glossary.md）にも追記する
```

## 5. やってはいけないこと

【事実】

- **回答を確認せずに社外へ送らない**
- **見せてはいけない文書を入れない**（指示書で「答えるな」と書いても、聞き方を変えれば引き出されます）
- **古い版の文書を残したまま新しい版を追加しない**

## 6. 精度について（期待値の調整）

【事実】

30問の評価で測定した実績です。

| 測定項目 | 結果 |
|---|---|
| 正答率 | 30問中 30問（共通の前置きのみの条件で） |
| **存在しない情報を聞いたとき** | **5問すべてで「記載がありません」と正しく回答。作り話はしませんでした** |
| 文書間の矛盾 | 検出して両方を提示できました |

**「分からないことを分からないと言える」ことは確認済みです。** ただし、

- 文書に書いていないことは答えられません（当然ですが、利用者は「AI なら知っているはず」と思いがちです）
- 文書が古ければ、古い答えを返します
- **精度は文書の質で決まります。** AI の問題ではなく、文書の整備状況の問題です
