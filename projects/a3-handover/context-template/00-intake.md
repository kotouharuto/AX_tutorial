# 00. 案件開始時に顧客に聞くこと

方式（既製 / GUI ツール / 自作）と配置を決めるための質問。

各項目は**「顧客に聞く言葉」「確認したいこと」「答えの例と対処」**の3点で構成する。
顧客に投げる文は「顧客に聞く言葉」だけ。残り2つは自分用。

**顧客が即答できない項目は「未決」として持ち帰り、誰がいつ決めるかを合意する。**

---

## 1. 外部サービスに文書を送ってよいか

**顧客に聞く言葉：**
「社内の文書を、Google や Anthropic などの外部の AI サービスに読み込ませることは、社内ルール上できますか？」
「できる場合、情シスや法務への申請は必要ですか？申請から承認まで、普段どのくらいかかりますか？」
「『外部に送る』がダメな場合、一時的に API で送って保存されないケースも含めてダメですか？」

**確認したいこと：**
既製方式（NotebookLM / Claude Projects）が選択肢に入るか。入らないなら構築工数が数日単位で増える。

**答えの例と対処：**
- 「特にルールはない」→ 既製方式で進められる。ただし後から情シスに止められる可能性があるので、着手前に一言入れてもらう
- 「申請すれば通る。2週間くらい」→ 既製方式。申請期間をスケジュールに入れる
- 「外部は一切ダメ」→ セルフホスト（Dify / 自作）＋ローカル LLM。「API の一時送信もダメか」を確認し、ダメなら生成も埋め込みもローカル
- 「分からない」→ 情シスの担当者を紹介してもらう。決まるまで着手しない

---

## 2. 誰が使うか

**顧客に聞く言葉：**
「この仕組みを使うのは、どの部署の何人くらいですか？」
「部署や役職によって、見せてよい文書と見せてはいけない文書は分かれますか？」

**確認したいこと：**
利用者ごとの出し分けが必要か。必要なら既製方式1つでは足りない。

**答えの例と対処：**
- 「情シス5人だけ」→ 出し分け不要。1環境で済む
- 「全社200人。人事規程は人事部だけ」→ 部署別に環境を分けるか、自作で認証・フィルタを組む。工数が大きく変わるので、「人事規程を外して全員向けだけにできないか」を先に聞く
- 「まだ決めていない」→ 未決。最初は少人数で試し、広げるときに再設計する前提で合意する

---

## 3. 文書の状態

### 3-1. 量と形式

**顧客に聞く言葉：**
「読み込ませたい文書は何件くらいありますか？今後も増えますか？」
「スキャンした PDF（紙を取り込んだもの）や、表が多い文書は含まれますか？」

**確認したいこと：**
自作や GUI ツールは画像 PDF を読めない。表は構造が壊れやすい。A-2 の失点の大半がこの2つ。

**答えの例と対処：**
- 「Word や Google ドキュメントがほとんど」→ どの方式でも扱える
- 「紙をスキャンした PDF が多い」→ 既製方式（画像を読める）を優先。自作なら OCR を組み込む工数を見積もる
- 「Excel の表が中心」→ 表の構造が壊れるかを、数件で先に試す

### 3-2. 版の管理

**顧客に聞く言葉：**
「経費精算規程のような社内規程は、改定したときに新しいファイルを作りますか？それとも同じファイルを上書きしますか？」
「新しいファイルを作る場合、古い版はどこに置いていますか？削除していますか？」

**確認したいこと：**
同じ規程の新旧が混ざる可能性。混ざると「文書によって記載が異なります」が増え、利用者の確認負荷が上がる（→ [記録](../../../docs/pitfalls/a3-knowledge-curation-beats-instructions.md)）。

**答えの例と対処：**
- 「上書きしている」→ 混在リスク低。最新版だけ投入
- 「年度ごとに別ファイルで同じフォルダに並んでいる」→ 混在リスク高。投入前に版を突き合わせる
- 「分からない」→ 文書一覧をもらい、同じタイトルの複数ファイルを探す

### 3-3. 文書間の矛盾

**顧客に聞く言葉：**
「手順書と規程で、書いてあることが食い違っている箇所に心当たりはありますか？（連絡先の内線番号が古い、など）」

**確認したいこと：**
矛盾があると AI は「両方示す」しかできない。顧客が把握していれば先に直せる。

**答えの例と対処：**
- 「ある。直せていない」→ 先に直すか、AI に「矛盾は両方示す」と指示するかを顧客と決める
- 「ない」→ 投入後に AI に矛盾を探させて、報告する（A-3 で Claude Project が自発的に矛盾5論点を列挙した）

## 4. 運用と引き継ぎ

**顧客に聞く言葉：**
「新しい文書ができたとき、誰がこの仕組みに追加しますか？」
「この仕組みを動かすアカウントは、誰の個人アカウントですか？それとも共用アカウントですか？」
「その人が異動や退職をしたとき、誰が引き継ぎますか？」

**確認したいこと：**
「作った人がいなくなったとき動き続けるか」。トリガーや OAuth は個人アカウントに紐づき、移管できない（→ [記録](../../../docs/pitfalls/a1-gas-trigger-cannot-be-transferred.md)）。

**答えの例と対処：**
- 「情シスの共用アカウントがある」→ それで構築。個人アカウントは使わない
- 「担当者個人のアカウントしかない」→ 退職時に止まることを明示し、共用アカウントの作成を依頼するか、引き継ぎ手順書に「再承認」を含める
- 「誰が追加するか決めていない」→ 未決。決まるまで「追加は依頼制で、こちらが行う」と仮置き

---

## 5. 予算の中身

**顧客に聞く言葉：**
「予算は、作るときの費用ですか？毎月の費用も含みますか？」
「AI の API 利用料（従量課金）は、御社のアカウントで払いますか？こちらで立て替えますか？」

**確認したいこと：**
無料枠は送信内容が学習に使われる（→ [記録](../../../docs/pitfalls/a1-gemini-free-tier-data-use.md)）。有料枠は誰の名義で契約するか。

**答えの例と対処：**
- 「構築費のみ。ランニングは想定していない」→ 有料 API が必要なら、月額の見積もりを先に出す
- 「御社のアカウントで」→ 顧客に API キーを発行してもらう。こちらのキーは使わない
- 「分からない」→ 未決。無料枠で検証し、本番移行時に決める、と合意する
