# 01. 指示書の骨格

AI（Claude Project 等）への指示文を書くための問い。**利用者は読まない。AI が読む。**
答えを書き終えたら、見出しなしの命令文に変換して指示欄に貼る。

---

## 1. 役割

- この環境は**誰が、何のために**使うか
- AI は「何をする担当」か（回答者 / 下書き作成者 / 分類者）
- AI が**判断してよい範囲**と、**人に回す範囲**の境界


## 2. 業務ルール

- 問い合わせや作業を**どう分類**するか
- **各分類の定義と例を書く**
  → *なぜ：分類名だけ書くと、同じ文書由来の問い合わせが別の分類に割れる（A-3 で実測）*
- 分類ごとに**誰に回す**か
- **緊急度・優先度**の基準。「高」と判定したら**何が起きるか**
  → *なぜ：基準が無いと AI の感覚で決まる。「高」で何も起きないなら項目自体が無意味*
- 対応の**期限**

```
```

## 3. 判断基準

- **文書に記載がないとき**、何と答えるか。定型文は
- **関連する記述はあるが、問いへの直接の答えがないとき**、どう扱うか
- **同じ規程に新旧版があるとき**、どちらを正とするか
  → *ただし、旧版はナレッジに入れない方が先（02 参照）*
- **文書間で記載が矛盾するとき**、片方を選ぶか、両方示すか
- **画像・表から読み取った情報**を、テキストと同じ確度で扱うか
- 迷ったとき、**どちらに倒す**か

```
```

## 4. 禁止事項

- **推測で答えてはいけない**領域（金額 / 期限 / 人事 / …）
- **代わりに実行してはいけない**こと（送信 / 申請 / …）
- **値とルールを区別して**、答えてはいけないものを書く
  → *なぜ：「パスワード等は答えない」と書くと、AI は「パスワードの文字数要件」まで隠す。「パスワードそのもの」と限定する（A-3 で実測）*
- 利用者の**個人情報**の扱い
- 文書に書いてあっても**答えてはいけない**ことがあるか
  → *あるなら、指示書で縛るのではなくナレッジに入れない（02 参照）*

```
```

## 5. 出力形式

- 回答の**構造**（結論 → 根拠 → 出典 …）
- **出典**を必ず付けるか
- 「記載なし」のときの**定型文**
- 人が読むか、機械が読むか（機械なら JSON で固定）
