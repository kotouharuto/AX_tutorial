# A-3 ステップ①：n8n で A-1 と同じ処理を組む

```
Google Sheets Trigger（1分ポーリング）
  → Filter（状態が空の行のみ）
  → HTTP Request（Gemini で分類）
  → Google Sheets Read（担当マスタ・executeOnce）
  → Code（JSON パース・検証・宛先解決）
  → Gmail（振り分けメール・フッター OFF）
  → Google Sheets Update（タイムスタンプ照合で書き戻し）
```

## 構成

| ファイル | 役割 |
|---|---|
| `docker-compose.yaml` | n8n セルフホスト（named volume・Asia/Tokyo・SECURE_COOKIE=false） |
| `workflow.json` | ワークフロー定義。**手書き JSON は内部形式と合わず、インポート後に GUI で修正が必要だった** |

## 動かすまでに必要なもの

1. GCP プロジェクト、API 有効化（Sheets / Gmail / Drive）、OAuth 同意画面、テストユーザー、クライアント ID
2. n8n クレデンシャル3本：Google Sheets OAuth2 / Google Sheets **Trigger** OAuth2 / Gmail OAuth2
3. Header Auth クレデンシャル（`x-goog-api-key` = Gemini キー）
4. A-1 のスプレッドシート（シート名を `回答` に変更済み。GAS 側 `Config.js` は未修正）

## GAS 版との差分（実測）

| 観点 | GAS（A-1） | n8n（A-3） |
|---|---|---|
| 構築時間 | 約2時間 | 約2日（OAuth 2h + 構築 2.5h + 詰まり） |
| 起動方式 | イベント駆動（送信の瞬間） | ポーリング（最短1分） |
| 要求スコープ | `spreadsheets.currentonly` | `spreadsheets`（全ファイル）+ Drive 2つ |
| OAuth 接続数 | 1 | 3 |
| 本番運用の前提 | なし | ホームページ・プライバシーポリシー URL（Google 要件） |
| トークン期限 | なし | テストモードは7日 |
| 行の特定 | `e.range.getRow()` で確実 | タイムスタンプ照合（同一秒は誤更新しうる） |
| ロジックの記述 | JS（ファイル分割可） | JS（Code ノード1つに集約） |
| 実行の可視性 | 実行ログ画面 | **ノードごとの入出力がキャンバスで見える**（明確な利点） |
| 設定の耐性 | ヘッダ名で動的解決 | GUI 設定はスナップショット。参照先変更で消える |
| メールのフッター | なし | 既定で n8n のフッター（OFF 可） |

## GAS との使い分け（自分の言葉・2026-09-15）

### 顧客への説明

> GAS は Google のサービスのみで構成でき、スプレッドシートを扱い、フォームなどでの回答をもとに
> LLM で自動分類・回答生成を行い、その結果をスプレッドシートのセルに自動記入します。
> 要するに**シートの中に GAS が住んでいる**ような状態です。
> 対照的に n8n は、シートを**外部参照**し、**複数サービスをチェーンのように繋ぎ**、自動化する手法です。
> 繋ぐための**鍵（OAuth）の管理が必要**なため、別途検討が必要です。

### 今回の題材を実案件で頼まれたら

GAS を推奨する。Google のサービス内で完結し、権限が「このシートだけ」で済み、
OAuth 設定が不要で、顧客の Google アカウント内に置けるのでそのまま顧客の資産になる。
外部 SaaS を跨がない案件なので、n8n の利点が活きない。

### n8n を選ぶ条件

外部 SaaS を跨ぎながら自動化すること。作成方法・運用方法をレクチャーし、
**適切に運用できる人材が社内に存在すること**を条件にする。
加えて、Google 側の本番運用要件（プライバシーポリシー URL 等）を顧客側が満たせること。
