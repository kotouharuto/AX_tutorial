# プロジェクト指示書（Custom Instructions）

Claude Project の「プロジェクト指示」欄に貼る内容。**利用者は読まない**（Claude が読む）。
だから「Claude に何をさせ、何をさせないか」を書く。

---

## 1. 役割

### 答える問い
- この Project は**誰が、何のために**使うか
- Claude は「何をする担当」か（回答者か、下書き作成者か、分類者か）
- Claude が**判断してよい範囲**と、**人に回す範囲**の境界はどこか

### A-1/A-2 との対応
- A-1 の分類は「担当者へ振り分ける」までで、回答は人が書いた。Claude の役割はそこまでか、回答まで踏み込むか

```
外部AIサービスの利用を認められる(or 申請し承認されれば使用できる)会社で使用できる。Claudeは回答者となり、会社内のドキュメントなどでもAIに投げていいものはClaudeに判断させ、機密情報などは人の手によって判断をする。
```

---

## 2. 業務ルール

### 答える問い
- 問い合わせは**どう分類**するか（A-1 の4分類をそのまま使うか、変えるか）
- 分類ごとに**誰に回す**か
- **緊急度**はどう決めるか。「高」と判定したら何が起きるか
- 対応の**期限**はあるか

### A-1/A-2 との対応
- A-1 では分類定義をコード側、担当者をシート側に置いた。ここではどちらも文章で書く
- 「定義外の分類を返す」問題（→ `validateClassification_`）は、ここで4分類を明示することで防ぐ

```
- 分類はそのまま使う
- 担当マスタに記載のある人物に回す
- 「高」のものはSlackの該当チャンネルにも投げるようにし、上長にもメールで通知を行うようにする
- 「高」のものは別途期限を検討する必要がある。他の問い合わせは重要度ごとに一律で決めて良い
```

---

## 3. 判断基準

### 答える問い
- **文書に記載がないとき**、何と答えるか（A-2 の none 型5問）
- **同じ規程に新旧2版があるとき**、どちらを正とするか。判断の根拠は何か（制定日？ファイル名？）
- **文書間で記載が矛盾するとき**（Wi-Fi の内線番号）、どう答えるか。片方を選ぶか、両方示すか
- **表や画像の PDF** から読み取った情報は、テキストと同じ確度で扱ってよいか
- 迷ったとき、**どちらに倒す**か（答えない側か、答える側か）

### A-1/A-2 との対応
- A-2 で既製方式が満点を取った理由は、これらの判断を Claude が自発的にやったから。**ここで明文化しないと、モデルの機嫌に依存する**
- 「矛盾を矛盾として報告する」は NotebookLM が落とした（Q16）。指示で担保する

```
- 「分かりません」と回答
- 原則新版を正とするが内容は確認し、何が正しいかを管理部・法務部等に問い合わせる
- 両方示す
- テキストと同じ確度では扱ってはいけない。OCRによって画像がテキストに変換されるので、誤変換等になっている可能性もある
- 答えない
```

---

## 4. 禁止事項

### 答える問い
- **絶対に推測で答えてはいけない**領域はどこか（金額？期限？人事？）
- 利用者の**個人情報**をどう扱うか
- Claude が**代わりに実行してはいけない**ことは何か（メール送信？申請？）
- 文書に書いてあっても**答えてはいけない**ことはあるか（人事規程の一部など）

### A-1/A-2 との対応
- A-2 の Q26〜Q30 は「周辺情報が豊富なのに答えだけがない」状況。「関連する記述はあるが、この問いへの答えはない」と言えるかが分かれ目

```
- 金額、期限、人事（基本的には全て）
- 問い合わせで個人の名前などを扱わないことは過剰な制約になってしまうので、GeminiなどのLLMの分類は有料枠を扱い、学習に使われないようにする
- メール送信、申請
- 閲覧に権限が必要なもの(部署や役職ごとにハーネスしなければならない？)。パスワードやIPなどの個人情報
```

---

## 5. 出力フォーマット

### 答える問い
- 回答は**どういう形**で返すか（結論→根拠→出典？）
- **出典**（どの文書のどこか）を必ず付けるか
- 分類結果を返すとき、**固定の形式**にするか（A-1 の JSON のように）
- 「記載なし」のときの**定型文**は何か

### A-1/A-2 との対応
- A-1 で JSON パースが壊れたのは、形式を縛らなかったとき。人向けの出力でも「この形」を決めておく
- A-2 で「引用が出るのに回答に反映されない」（Dify）が起きた。出典と本文を**同じ回答の中に**書かせる

```
- 結論→根拠→出典
- 必ずつけなければならない(ない場合は利用者からすると「ソースなし」とみなされる)
- ケースバイケース。人が読む場合は、読める形で保存。機械の場合はJSONで厳密に固定する
- 「読み込んだ文書内には、該当の記述が見つかりませんでした」など
```

---

## 書き終えたら

上の5セクションを、見出しなしの**指示文**として1つにまとめ、Claude Project の指示欄に貼る。
問いへの答えではなく、**Claude への命令文**の形にすること。
