# 手順書（利用者向け）

**Project の外**に置く。利用者（非エンジニア）が読んで、問い合わせ対応を1件こなせる粒度で書く。

A-3 ステップ⑥で、**この題材を知らない人に渡して試す**。
詰まった箇所が、この手順書の欠陥。

---

## 答える問い

### 開始
- 利用者は**どこから**始めるか（URL？ブックマーク？）
- **最初に何を入力**するか。問い合わせ本文をそのまま貼るのか、整形するのか

### 実行中
- Claude の回答を**そのまま使ってよい**か、必ず人が確認するか
- 「記載がありません」と返ってきたら、**次に何をする**か
- 回答が**間違っていると思ったら**、どうするか

### 終了
- 対応が終わったら、**どこに何を記録**するか（A-1 のシート？別の場所？）
- 誰に**報告**するか

### 困ったとき
- Project が**開けない**とき（権限？リンク切れ？）
- 回答が**明らかにおかしい**とき（誰に言うか）
- **文書を追加・更新**したいとき（誰がどうやるか）← A-3 の「ルール変更時に誰が直すか」

### やってはいけないこと
- Claude の回答を**確認せずに**社外へ送る、など

---

## 形式

見出し＋番号付き手順。1手順1操作。画面のどこを押すかまで書く。
**「〜を確認します」で終わる手順は、何を見て何と判断するかまで書く。**

```
### 開始
- URL
- 整形を行った上で入力とする
### 実行中
- 必ず人が確認
- 社内規定を目視で確認し、それでも分からない場合は担当部署や担当者に確認を取る
- 同上で、目視or担当者で確認を取る
### 終了
- 基本的にはスプレッドシートに記載をする
- システムの管理者(GAS等の管理者)に報告を行う
### 困ったとき
- 社内のClaudeの管理者に問い合わせる
- 当該の質問内容の回答に関しては、担当部署や担当者に確認を取り、回答の質に関してはClaude Projects管理者に相談
- 情シス等の担当者が行う
```
