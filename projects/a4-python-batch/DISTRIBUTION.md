# 配布手順書（Python 未導入の PC 向け）

このバッチを、Python が入っていない PC で動かすための手順。

> **重要：この手順は Windows 実機で検証していません。**
> 作成者が Windows 環境を持っていないため、設計と手順の記述にとどまります。
> CI（GitHub Actions の windows-latest）でコード自体は動作確認済みですが、
> **配布形式での起動は未確認**です。初回導入時は立ち会いを想定してください。

---

## 配布方式の選択

3つの方式を検討し、**方式B を推奨**します。

| 方式 | 利用者の手間 | 配布サイズ | 更新のしやすさ | 判定 |
|---|---|---|---|---|
| A. Python をインストールしてもらう | 大（管理者権限が要る場合あり） | 小 | 容易 | 企業 PC では権限の問題が出やすい |
| **B. uv の同梱スクリプト** | **中** | 小（初回のみ DL） | **容易** | **推奨** |
| C. PyInstaller で単一 exe 化 | 小（ダブルクリック） | 大（100MB超） | 再ビルドが必要 | 起動が遅い（後述） |

### なぜ方式C（exe 化）を推奨しないか

エンドポイント保護（企業 PC にはほぼ確実に入っている）が、
**新規ファイルを1つずつスキャン**します。開発機での実測では、

```
初回実行: 11分14秒（うち CPU 時間 0.7 秒。残りは全部スキャン待ち）
2回目以降: 0.37 秒
```

PyInstaller の exe は**単一の巨大なバイナリ**なので、初回起動時に丸ごとスキャンされます。
数十秒から数分かかる可能性があり、利用者は「動かない」と判断します。

方式B なら、スキャンは細かいファイル単位で分散し、途中経過も見えます。

## 方式B：uv 同梱スクリプトでの配布

### 配布物

```
問い合わせ集計バッチ/
  実行.bat              ← 利用者はこれをダブルクリック
  src/                  ← プログラム本体
  pyproject.toml
  uv.lock               ← バージョンを固定（環境差をなくす）
  input/
    excel/              ← ここに支店ファイルを置いてもらう
    pdf/
  output/               ← 結果がここに出る
  README_利用者向け.txt
```

### 実行.bat の内容

```bat
@echo off
chcp 65001 > nul
cd /d "%~dp0"

echo 初回は準備に数分かかります。画面を閉じずにお待ちください。
echo.

where uv > nul 2>&1
if errorlevel 1 (
    echo uv をインストールします...
    powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
    set "PATH=%USERPROFILE%\.local\bin;%PATH%"
)

uv run python src/main.py
if errorlevel 1 (
    echo.
    echo 警告またはエラーがあります。output\load_report.txt を確認してください。
)

echo.
pause
```

`pause` を入れているのは、**エラーが出た瞬間にウィンドウが閉じるのを防ぐため**です。
利用者から「一瞬で消えた」という報告が来る典型的な原因になります。

### 利用者向けの案内文

```
【初回のみ】
1. 実行.bat をダブルクリックしてください
2. 「準備中」と出たまま数分かかります。画面を閉じないでください
   ※ セキュリティソフトの確認が走るためです。2回目以降は数秒で終わります
3. 「完了」と出たら終わりです

【毎月の作業】
1. input\excel\ に各支店から届いたファイルを入れる
2. input\pdf\ に各支店の報告 PDF を入れる
3. 実行.bat をダブルクリック
4. output\ に結果が出ます

【うまくいかないとき】
- output\load_report.txt を開いて「警告」の欄を見てください
- 画面が一瞬で消える場合は、実行.bat を右クリック →
  「PowerShell で実行」を選ぶと、メッセージが残ります
```

## Windows 固有のリスク（未検証）

実機で確認できていないため、以下は**想定される問題**です。

| 項目 | 想定される問題 | 対処の方針 |
|---|---|---|
| **PowerShell の実行ポリシー** | 組織のポリシーで `irm \| iex` がブロックされる | uv を手動でインストールしてもらうか、管理者に例外申請 |
| **エンドポイント保護** | 初回が数分かかる。ダウンロードがブロックされる場合も | 案内文に明記。ブロックされたら情シスに申請 |
| **文字コード** | `chcp 65001` を入れているが、旧環境では文字化けの可能性 | 出力を確認して調整 |
| **パス区切り** | コードは `pathlib` を使用。CI（windows-latest）で確認済み | 対処済み |
| **日本語を含むパス** | ユーザー名が日本語の場合に問題が出ることがある | 未検証。要確認 |
| **ネットワークドライブ** | `\\server\share` 上での実行は挙動が異なる | ローカルにコピーして実行してもらう |
| **Excel が開いたまま** | 対象ファイルを Excel で開いていると読めない | 案内文に「Excel を閉じてから実行」と記載 |

## 実機で確認すべきこと（Windows 環境が手に入ったら）

```
□ 実行.bat のダブルクリックで起動するか
□ 初回の所要時間（案内文の「数分」が妥当か）
□ uv の自動インストールが通るか（実行ポリシー）
□ 日本語を含むパスで動くか
□ 出力ファイルが文字化けしないか
□ エラー時に pause で画面が残るか
□ 対象 Excel を開いたまま実行したときのエラーメッセージが分かりやすいか
```
