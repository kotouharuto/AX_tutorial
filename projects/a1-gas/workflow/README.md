# A-1 ステップ③：実務が回る1本

```
Googleフォーム受付 → Gemini で分類 → 担当者へ振り分けメール → シートに記録
```

工程書：[docs/process/10-A1-gas.md](../../../docs/process/10-A1-gas.md)

## ファイル構成

| ファイル | 役割 |
|---|---|
| `Config.js` | 定数。シートに出すべきでない構造的な設定のみ |
| `Setup.js` | 初期セットアップ（フォーム生成・担当マスタ作成・トリガー登録）と診断 |
| `Main.js` | 本体。トリガー入口・行処理・シート書き込み・失敗時の通知 |
| `Classifier.js` | Gemini 呼び出しと JSON パース |
| `Routing.js` | 担当マスタの読み込みと宛先解決 |

## セットアップ手順

1. `clasp push --force`
2. エディタで `setup` を実行（フォーム・担当マスタ・トリガーが作られる）
3. スクリプトプロパティに `GEMINI_API_KEY` と `FALLBACK_TO` を設定
4. 担当マスタシートに担当者アドレスを記入
5. `checkSetup` を実行して前提を確認
6. フォームから送信

## oauthScopes と必要理由

**自動推論に任せず手で書いている。** 推論はスコープを増やす方向にしか働かず、
増えたことに気づけないため（→ [記録](../../../docs/pitfalls/a1-gas-mailapp-vs-gmailapp-scope.md)）。

| スコープ | 必要理由 |
|---|---|
| `spreadsheets.currentonly` | フォーム回答と担当マスタの読み書き。コンテナバインドなので**このシートのみ**で足りる。スタンドアロン構成なら `openById` が必要になり、全スプレッドシートへの権限を要求することになる |
| `forms` | `setup` でフォームを生成し、回答先をこのシートに設定するため |
| `gmail.send` | 担当者への振り分けメールとエラー通知の送信。**受信は不要なので `readonly` は要求しない** |
| `script.scriptapp` | フォーム送信トリガーの登録と重複確認 |
| `script.external_request` | `UrlFetchApp` で Gemini API を呼ぶため |

**要求していないもの：** `script.send_mail`（`MailApp` 用。`GmailApp` で足りるため不要）、
`drive`（ファイル探索をしないため不要）、`spreadsheets`（全シート権限。currentonly で足りる）。

## 設計判断

| 判断 | 理由 | 失うもの |
|---|---|---|
| 振り分け先をシートで持つ | 非エンジニアが変更できる（A-3 のルール変更に効く） | 入力検証の責務が増える |
| 分類カテゴリはコードで持つ | プロンプトと担当マスタの両方に影響するため、片方だけ変わると壊れる | 追加時に開発者が要る |
| 担当者未設定でも止めない | 止めると問い合わせが宙に浮き誰も気づかない | 誤配の可能性 |
| 分類結果を検証する | モデルは定義外の値を平気で返す | 定義変更時に throw が増える |
| 自動リトライを実装しない | 原因を直さず再試行するとクォータを浪費して同じ失敗を積む | 一時障害で手動対応が要る（ステップ④で実装予定） |

## 既知の制限

- **モデル名は時間で腐る**（→ [記録](../../../docs/pitfalls/a1-gemini-model-name-rot.md)）。
  止まったら `Config.js` の `GEMINI_MODEL` を差し替える。
- **Gemini 無料枠は送信内容が学習・人間レビューの対象**
  （→ [記録](../../../docs/pitfalls/a1-gemini-free-tier-data-use.md)）。実データを流さない。
- 失敗行の再処理は `retryFailedRows` の手動実行。
- ステップ④が未実装：6分制限の分割実行、`LockService` による排他、指数バックオフ。
