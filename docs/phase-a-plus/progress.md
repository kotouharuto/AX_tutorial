### 観察：stdio で print すると（方針書の観察対象）

**SDK 2.3.0 では、素朴な print() で呼び出しは壊れなかった。** 公式ドキュメントの
「stdout に書くとサーバが壊れる」は、この組み合わせでは再現しなかった。

| ケース | 出力先 | 呼び出し |
|---|---|---|
| 起動時に print | **通信路** | 成功 |
| ツール内で print（改行あり） | **通信路**（バッファに残り、終了時に出た） | 成功 |
| ツール内で print（`flush=True`） | stderr | 成功 |

理由はサーバとクライアントの二重の防御：サーバは起動時に stdout を退避して fd 1 に
stderr をつなぎ直す。クライアントは JSON でない行を捨てる。

**「print しても安全」とは結論しない。** 実際に通信路へ不正な行が流れており、
壊れなかったのはこの Python クライアントが寛容だから。
**Claude Code・Desktop は別実装のクライアント**なので、接続時に確かめる。
**壊れないので入っても気づけない**ため、本番コードに print が無いことを静的に検査している。

CLAUDE.md の「**動いてしまった場合は壊し方を考える**」に従い、改行なしの print も試したが、
`flush=True` で即座に書いたため退避先（stderr）に出て、やはり壊れなかった。
