# Gemini API の無料枠は送信内容が学習に使われる（納品では有料枠が前提）

- **ブロック：** A-1
- **日付：** 2026-08-25
- **一般性：** どの環境でも（技術ではなく利用規約の制約）
- **溶かした時間：** 約 0.2 時間（調査）

## 事象

分類に Gemini API を選定。Google AI Studio 経由で無料枠が使えるため、
検証は無料枠で進められる。**ただし無料枠と有料枠でデータの扱いが根本的に違う。**

| | 無料枠（Unpaid Services） | 有料枠（Paid Services） |
|---|---|---|
| 送信内容の利用 | **Google の製品改善・ML 学習に使われる** | 学習に使われない |
| 人間によるレビュー | **あり**（Google アカウント・APIキー・Cloud プロジェクトとの紐付けを外した上で読まれる） | なし |
| ログ保持 | — | 不正利用検知目的で限定期間のみ |

出典：[Gemini API Additional Terms of Service](https://ai.google.dev/gemini-api/terms) /
[Data Logging and Sharing](https://ai.google.dev/gemini-api/docs/logs-policy)

## なぜ落とし穴か

**動作は完全に同じなので、気づく機会がない。**
検証環境（無料枠）でそのまま納品すると、顧客の問い合わせ内容・社内文書が
学習対象になり、人間のレビュー対象にもなる。多くの組織で契約違反になる。

さらに悪いのは、**課金を有効化しないと無料枠のまま**という点。
「API キーを発行して動いた」で止まると、無料枠であることに気づかない。

## 対処

- 検証は無料枠でよい。**ただし架空データに限る。**
  今回の題材（架空の問い合わせフォーム）はフォーム説明にも
  「実データは入力しないでください」と明記した。
- 実案件では**課金を有効化して有料枠にする**。これは技術選定の前提条件であって、
  価格交渉の材料ではない。見積もりに API 費用を含める根拠になる。
- 提案時点で「どのモデルを、どの枠で使うか」を明示する。
  ここを曖昧にしたまま進めると、後から情シス・法務で止まる。

## 他のモデルでも確認すべきこと

無料枠・試用枠のデータ利用条件はベンダごとに違い、**変わる。**
選定時に必ず現時点の規約を確認する。「前に調べたから大丈夫」は通用しない。

## 他人の環境に納品するときの含意

**技術選定の制約が、技術以外の理由で決まる典型例。**
「精度が良いモデル」ではなく「その組織が送信して良いモデル」が選定基準になる。
引き渡しドキュメントには、使用モデルと課金状態を明記する
（A-3 の「作った人がいなくなったとき」に、誰も分からなくなるため）。
