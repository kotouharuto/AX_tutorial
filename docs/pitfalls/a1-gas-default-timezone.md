# clasp が生成する appsscript.json の timeZone が America/New_York になっている

- **ブロック：** A-1
- **日付：** 2026-08-25
- **一般性：** どの環境でも（clasp で新規作成すれば必ず）
- **溶かした時間：** 約 0.05 時間（気づけば一瞬、気づかなければ後で高くつく）

## 現象

`clasp create-script` が生成する `appsscript.json`：

```json
{
  "timeZone": "America/New_York",
  ...
}
```

日本で使う前提でも、既定でニューヨーク時間になる。

## 原因

clasp のテンプレート既定値。ロケールを見ていない。

## なぜ重大か

このタイムゾーンは**スクリプト全体の時刻の基準**になる。実害が出る場所：

- **時間主導トリガー**：「毎日9時」が現地時間の9時になり、日本時間では別の時刻に走る
- `new Date()` / `Utilities.formatDate()` の既定タイムゾーン
- シートへ書き込む日時、メール本文の日時表記
- **日付の境界**：日次バッチの「今日の分」が、日を跨いでずれる

**症状が出るのが導入からしばらく後になる**（トリガーを仕掛けて初めて気づく）ため、
原因究明に時間がかかるタイプの不具合。

## 対処

作成直後に修正する。マニフェスト変更なので push には `--force` が要る
（→ [clasp push の silent skip](a1-clasp-push-silent-skip.md)）。

```json
{
  "timeZone": "Asia/Tokyo"
}
```

## 他人の環境に納品するときの含意

**新規プロジェクトのチェックリストに `timeZone` を入れる。**
相手の組織が複数拠点にまたがる場合、どの拠点の時刻を基準にするかは
技術ではなく**業務の決めごと**なので、引き渡しドキュメントに明記する。
