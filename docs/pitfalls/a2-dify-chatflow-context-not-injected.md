# Dify チャットフローで「引用」は出るのに回答に反映されない（{{#context#}} の手動挿入が必要）

- **ブロック：** A-2
- **日付：** 2026-09-13
- **一般性：** Dify のチャットフロー／ワークフローで LLM ノードを使う全ケース
- **溶かした時間：** 約 0.5 時間

## 事象

チャットフローで `ユーザー入力 → 知識検索 → LLM → 直接応答` を配線し、
LLM ノードの「コンテキスト」欄に `知識検索 / result` を設定した。

プレビューで質問すると、**画面下に「引用: ASSET-402_社用車の利用規程.md」と正しい文書が表示される**のに、
回答は「文書に記載がありません」。

## 原因

DB の実行ログ（`workflow_node_executions.process_data`）で LLM に送られたプロンプトを見ると：

```
[system]
以下は社内文書についての質問です。
...
--- 検索された文書 ---
（空）
```

**コンテキスト変数は LLM ノードに届いているが、プロンプト内で参照されていない。**

基本チャットボット（オーケストレーション「基本」）では、コンテキストを設定すると
プロンプトに自動挿入される。**チャットフローの LLM ノードでは自動挿入されず、
SYSTEM プロンプト内に `{{#context#}}` を明示的に置く必要がある。**

## なぜ気づきにくいか

- 「引用」表示は知識検索ノードの出力から生成されるため、**LLM が読んでいなくても表示される**
- 見た目は「検索は成功、LLM が答えなかった」に見えるので、モデルやプロンプトの言い回しを疑う
- トークン数（190前後）が少ないのが唯一の手がかりだったが、比較対象がないと気づけない

## 対処

LLM ノードの SYSTEM 欄で、コンテキストを埋め込みたい位置にカーソルを置き、
**`/` を入力 → メニューから「コンテキスト」を選ぶ。** 青いバッジ（`context`）が挿入される。

文字として `{{#context#}}` と打っただけでは認識されないことがある。必ずメニューから入れる。

### 切り分けの手段

Dify の画面では「何が LLM に渡ったか」は見えない。**DB を直接見るのが最短だった。**

```sql
-- LLM に実際に送られたプロンプト
SELECT process_data::json->'prompts' FROM workflow_node_executions
WHERE node_type='llm' ORDER BY created_at DESC LIMIT 1;

-- コンテキスト変数の中身
SELECT inputs::json->>'#context#' FROM workflow_node_executions
WHERE node_type='llm' ORDER BY created_at DESC LIMIT 1;
```

これで「変数は届いているがプロンプトに無い」が一目で分かった。

## 他人の環境に納品するときの含意

- チャットフローを納品するなら、**「引用が出ているのに答えない」は最初に疑う症状**として
  引き渡しドキュメントに書く。利用者はこの状態を「AI が間違えた」と解釈する。
- GUI ツールは「動いているように見える」情報（引用、ステータス、成功マーク）を出すが、
  **「何が渡ったか」は DB か API ログを見ないと確認できない。**
  GUI で完結する運用を約束するなら、この確認手段を残しておく必要がある。
