# 実行時間6分制限に当たる（実測：API 分類は約87件で打ち切り）

- **ブロック：** A-1
- **日付：** 2026-08-26
- **一般性：** どの環境でも（GAS の実行時間上限）
- **溶かした時間：** 約 0.8 時間（意図的な再現実験）

## 実測値（Phase B の見積もりに使える数字）

150件のダミー問い合わせを Gemini API で分類させ、分割なしで一括処理した。

| 経過 | 処理件数 | 1件あたり |
|---|---|---|
| 84秒 | 20件 | 4.20秒 |
| 202秒 | 50件 | 4.04秒 |
| 329秒 | 80件 | 4.11秒 |
| **360秒** | **約87件で強制終了** | — |

```
エラー: Exceeded maximum execution time
```

**1件あたり約4.1秒（ほぼ一定）。6分で処理できるのは約87件。**

「100件を API に投げれば簡単に超える」は事実だった。
**この数字があれば「何件までなら1実行で回るか」を即答できる。**

## 強制終了の性質（分割実行が要る理由）

**`Exceeded maximum execution time` は `catch` できない。`finally` も走らない。**

つまり「落ちてから片付ける」ことは原理的に不可能で、
**落ちる前に自分で止まるしかない。**

| | 強制終了 | 自主中断（分割実行） |
|---|---|---|
| どこまで処理したか | **分からない** | 記録済み |
| 再開 | できない（先頭から探し直し） | カーソルから継続 |
| 後片付け | 走らない | 実行できる |

同じ「途中で止まる」でも、**再開できるかどうかが決定的に違う。**

## 対処：分割実行

```js
for (; row <= lastRow; row++) {
  // 安全域を超えたら、処理を続けずに中断する。
  // 「あと1件くらい」で続けると、その1件がリトライを挟んだ瞬間に強制終了される。
  if (Date.now() - startedAt > maxRuntimeMs) {
    props.setProperty(PROP_BATCH_CURSOR, String(row));   // 位置を保存
    scheduleBatchResume_();                              // 継続トリガーを張る
    return;
  }
  processOneRow_(sheet, row);
}
props.deleteProperty(PROP_BATCH_CURSOR);  // 完走したらカーソルを消す
```

**結果：150件を分割実行で完走（完了150 / 失敗0 / 未処理0）。**

### 設計判断1：安全域は「平均」ではなく「最悪ケース」で決める

既定は **4.5分（90秒の余裕）**。1件4.1秒なら余裕すぎるように見えるが、
**リトライを挟んだ1件は数十秒かかりうる。**

安全域を詰めすぎると、たまに来る遅い1件で強制終了され、
**再開位置を保存する前に落ちて状態が壊れる。**
中途半端に守るくらいなら、余裕を多く取って再開回数が増える方が安全。

### 設計判断2：安全域はコード定数ではなく上書き可能にする

1件あたりの処理時間は環境で変わる（API の応答速度、リトライの頻度）。
**適切な安全域は納品先で測らないと分からない。**

定数直書きだと調整のたびにコード変更と再デプロイが要る。
`PropertiesService` で上書き可能にすれば運用側で調整できる。
振り分け先をシートに出したのと同じ判断。

### 設計判断3：再開位置はカーソルで持つ

シートの状態列だけでも再開はできるが、毎回先頭から未処理行を探すと
**件数が増えるほど走査コストが上がり、そのぶん処理できる件数が減る。**
処理が進むほど遅くなる設計になってしまう。

## 継続トリガーの落とし穴

`ScriptApp.newTrigger(...).timeBased().after(60 * 1000).create()` で作る
使い捨てトリガーは、**実行後も残る。**

放置すると溜まり続け、**トリガー数の上限（1スクリプト・1ユーザーあたり20個）**に当たり、
「トリガーを作れない」という別の障害になる。分割実行が途中で止まる。

対処：**実行の冒頭で自分の継続トリガーを削除する。**
後始末を最後ではなく先頭でやることで、異常終了しても溜まらない。

## 他人の環境に納品するときの含意

- **「今は動いている」は根拠にならない。** 件数が1.5倍になれば止まる。
  引き渡し時に「何件までなら1実行で回るか」を数字で伝える。
- 分割実行は**冪等性が前提**。再開時に同じ行を処理しても壊れない設計が要る
  （→ [多重起動](a1-gas-trigger-concurrency.md)と同じ話）。
- 処理が途中で止まったとき、**利用者から見て「終わったのか途中なのか」が
  分かる必要がある。** 進捗を業務側から見える場所に出す。
