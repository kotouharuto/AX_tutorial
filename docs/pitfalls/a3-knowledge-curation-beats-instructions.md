# 設計で「外す」と決めた文書が投入されていた（ナレッジ管理は指示書に優先する）

- **ブロック：** A-3
- **日付：** 2026-09-17
- **一般性：** どの環境でも（RAG・Project 全般）
- **溶かした時間：** 約 0.3 時間

## 事象

用語集の設計（02-glossary.md）で「旧版の規程2ファイルは**ナレッジから外す**」と決めた。
指示書には「文書間で矛盾があれば両方示して管理部門への確認を促す」と書いた。

30問を投げた結果、**8問が「文書によって記載が異なります」という矛盾扱い**になった。
うち5問は、旧版が残っていたことによる矛盾だった。

```
[05] Q14  REG-001-2023（翌月10日）／REG-001-2025（翌月5日）
[10] Q21  REG-001-2023（12,000円）／REG-001-2025・TBL-501（15,000円）
[17] Q13  同上
[23] Q18  REG-002-2024（負担なし）／REG-002-2025（3,000円）
[29] Q15  REG-002-2024（週2日）／REG-002-2025（週3日）
```

**旧版2ファイルを削除して再投入したら、5問すべてが単純な正答になった。**

## 原因

設計書で決めたことが、投入作業に反映されていなかった。
60ファイルをまとめてドラッグ＆ドロップしたときに、除外対象が混ざった。

**「決めたこと」と「入っているもの」を突き合わせる手順が無かった。**

## なぜ重要か

指示書は「矛盾があれば両方示す」と正しく機能した。
つまり**指示書は間違っていないのに、利用者から見れば「5問も確認が要る」という使いにくい状態**になった。

**ナレッジに何を入れるかの管理は、指示書の判断基準より前段で効く。**
矛盾を「どう扱うか」を指示書で決めるより、矛盾を「作らない」方が利用者の負担は小さい。

A-2 で Dify が「混在しています」で止まった問題も、根本は同じ。
既製方式（Claude Projects・NotebookLM）が自発的に新版を選んだから見えにくかっただけで、
**旧版を入れなければ、どの方式でもこの問題は発生しなかった。**

## 対処

### 投入前チェックリスト（03-procedure.md に追加）

```
□ 設計書の「外す」リストと、投入するファイル一覧を突き合わせた
□ 同じ文書番号（REG-001 等）で複数の版が無いことを確認した
□ 投入後、ナレッジのファイル数が設計書の想定と一致することを確認した
```

### 指示書の「矛盾の扱い」は残す

旧版を外しても、IT-102 と IT-103 の内線番号のような**意図せず生まれた矛盾**は残る。
指示書の「両方示す」はそのための最終防衛線であって、旧版混入への対処ではない。

## 併せて見つかった指示書の穴（2件）

**分類・緊急度の基準が無かった。** 「分類は A-1 のまま」と書いたが、A-1 のカテゴリ定義を
指示書に転記していなかった。結果、同じ IT-110 由来の問い合わせが「システム障害」と「その他」に割れ、
緊急度はほぼ全部「低」になった。基準を追記して修正。

**セキュリティの範囲が広すぎた。** 「パスワード等の具体的な値は答えない」を、
Claude は「パスワードに関する情報全般に注意書き」と拡張解釈した。
「12文字以上」は要件であって値ではない。「パスワードそのもの・接続キーそのもの」と限定して修正。

## 他人の環境に納品するときの含意

- **設計書に「外す」と書いても、投入する人が違えば入る。** 投入手順に突き合わせを組み込む。
- 顧客の文書は、旧版が「アーカイブ」フォルダに残っているのが普通。
  **投入対象を顧客と一緒に決める作業**が、精度に最も効く。
- 指示書のチューニングより、ナレッジの選別に時間を使う。
