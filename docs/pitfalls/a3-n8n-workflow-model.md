# n8n のワークフロー構築で踏んだ8件（GAS では起きなかったもの）

- **ブロック：** A-3
- **日付：** 2026-09-14〜15
- **一般性：** n8n の処理モデルに起因するもの。他のノードベースツール（Make, Zapier）でも同型
- **溶かした時間：** 約 2.5 時間（GAS 版の実装は約1時間）

A-1 の GAS 版（フォーム受付 → 分類 → 振り分け → 記録）を n8n で組み直した。
処理内容は同一なのに、GAS には無い概念で8回止まった。

## 1. 前ノードのアイテム数だけ次ノードが走る

```
フォーム回答トリガー   5 items
担当マスタ            30 items   ← 5 × 6行
Gemini分類            30 items   ← API を30回叩いた
```

**n8n は「前のノードが出したアイテムごとに、次のノードを実行する」。**
参照データ（担当マスタ6行）を読んだ後に Gemini を置くと、6回走る。

対処：参照データのノードに `executeOnce` を設定し、順序を
`トリガー → Gemini → 担当マスタ → Code` に変えて、参照は `$('担当マスタ')` で名前引きする。

GAS では `readRoutingTable_()` を1回呼ぶだけで、この概念自体が無かった。

## 2. `.first()` は下流のフィルタと無関係

Filter で行7だけ通しても、`$('フォーム回答トリガー').first()` は**トリガーが出した最初のアイテム＝行2**を返す。
毎回行2を処理し、行7は放置された。

対処：参照先を Filter 後のノード `$('未処理のみ').first()` に変える。
正しくは `.item`（ペアリングされた上流アイテム）を使うべきだが、Code ノードのモード変更が要る。

GAS の `e.range.getRow()` は「今まさに送信された行」を指すので、この混乱は起きない。

## 3. トリガーの出力に `row_number` が無い

読み取りノードは `row_number` を出すが、**トリガーノードは出さない**。同じ Google Sheets でも非対称。
行番号で照合する設計が成立せず、タイムスタンプ照合に変更した（同一秒の2件は誤更新しうる）。

## 4. シート名にスペースがあると Update が失敗

`フォームの回答 1!E` の範囲指定で `Unable to parse range`。A1 記法のクォートが付いていない。
GAS では問題なく動いていた名前。シート名を `回答` に変更して回避（GAS 側の Config も要修正）。

## 5. シート名を変えると列マッピングが全部消える

n8n の GUI 設定は**設定時点のスナップショット**。参照先のシート名を変えた瞬間に、
「Column to match on」も「Values to Update」も空に戻った。

GAS では `ensureExtraHeaders_()` でヘッダ名から列位置を毎回動的に解決していたので、名前変更に耐えた。
「業務ルールが変わったとき、誰がどこを直すのか」（A-3 の4点）が具体的に見えた。

## 6. 手書きの JSON は GUI の内部形式と合わない

`matchingColumns` を JSON に書いても「required」エラー。GUI で設定し直しても直らず、
ノードを削除して新規作成する必要があった。JSON 由来の壊れた状態が GUI で上書きできない。

**n8n のワークフロー JSON は手書きに向かない。** GUI で作ってエクスポートはできても、
書いて読ませるのは脆い。GAS はコードそのものなのでテキストで書いて push すれば確実に反映される。

## 7. 冪等性チェックを移植し忘れた

GAS 版の `processRow_()` にあった「状態列が埋まっていたらスキップ」を n8n 版に入れておらず、
テスト実行のたびに同じ行を再処理してメールが**5通**飛んだ。

対処：トリガー直後に Filter（状態 is empty）を置く。Gemini の前に置くことが重要。
**A-1 で得た教訓は、ツールを変えると自動では移植されない。**

## 8. Gmail のフッターが勝手に付く

```
--- This email was sent automatically with n8n https://n8n.io
```

Gmail ノードの「Append n8n Attribution」が既定 ON。顧客宛メールにツール名が入る。
Dify のロゴ削除不可と同じ構造で、**無料ツールは自分の存在を主張する。**

## 他人の環境に納品するときの含意

- n8n の「ノーコード」は**配線だけ**。Code ノードの中身は GAS とほぼ直訳で、ロジックはコードのまま。
- 上記8件のうち **1・2・5 は「動いているように見えて別の行を処理している」**タイプ。
  A-1 から繰り返し出ている構造が、ノードベースツールではより見えにくい。
- GAS 2時間 vs n8n 2日。**「GUI だから速い」は、その GUI の処理モデルを知っている人の話。**
