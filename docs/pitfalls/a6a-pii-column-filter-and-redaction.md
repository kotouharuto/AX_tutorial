# 個人情報を列で絞っても漏れた。値で伏せたら、今度は事実と違う目印を作った

- **ブロック：** A-6a
- **日付：** 2026-10-14〜15
- **一般性：** どの環境でも（汚れた業務データを LLM に渡すとき）
- **溶かした時間：** 約 1.5 時間

## 現象

A-1 の問い合わせ記録シートを MCP のツールで Claude に渡した。
お名前・メールアドレス・担当者の**列**は返さない設計にした。

**1回目（列で絞る）：** 実データで呼ぶと、**Claude 自身が漏れを指摘した。**

| 行 | 中身 |
|---|---|
| ある行 | 「状態」列に**メールアドレス** |
| 別の行 | 「内容」列が**メールアドレスだけ** |

さらにサーバの説明（`instructions`）に「問い合わせ記録には個人を特定できる列は含まれない」と書いていた。
**保証できていない保証を宣言していた。**

**2回目（値でも伏せる）：** メールアドレスの形と、同じ行のお名前列の値を他の列から伏せた。
すると、ある行の**日時欄が `[氏名]` に置き換わった。** Claude はそれを見てこう説明した。

```
日時欄に氏名が入っている＝列ずれ
```

**事実と違う。** シートを確認すると、その行の**お名前列に日時（`2026/08/25 22:46:31`）が入っていた。**
処理が日時を「名前」とみなし、日時欄の同じ文字列を伏せていた。

## 再現手順

1. 列ずれした行を含むシートを用意する（お名前列に日時、状態列にメールアドレスなど）
2. 除外する列を決めて、それ以外の列を返す → 列ずれで移った個人情報が出る
3. 同じ行の除外列の値で、他の列を伏せる → お名前列に日時がある行で、日時欄が `[氏名]` になる

## 原因

**どちらも「データが正しい列に入っている」前提に依存していた。**

- 列で絞る設計は、列ずれした行では、個人情報が**返してよい列に移っていても**止められない
- 同じ行の値で伏せる設計は、列ずれした行では、**お名前列に入っているのが名前とは限らない**。
  外れると、関係ない値を伏せて誤った目印を作り、逆に本当の名前は伏せられない

列ずれは A-1・A-3 の実験（n8n の書き込みなど）で生じたもの。**実データは必ずこうなる。**

**テストのデータが綺麗だったので、どちらもテストは通っていた。**

## 対処

段階を3つ重ねた（GAS 側に実装。Python 側の誤りで漏れないように、返す内容の決定はデータの近くで行う）。

| 段階 | 処理 |
|---|---|
| 1. 列ずれを判定する | 日時欄が日時の形でない／**お名前列が日時かメールの形**／メールアドレス列・担当者列がメールの形でない／状態・分類・緊急度が想定外の値 |
| 2. **列ずれした行は中身を出さない** | 内容と詳細を `[列ずれのため非表示]` にし、理由を警告に入れる。分類など定型の値だけ返す |
| 3. 正常な行だけ値で伏せる | 同じ行の除外列の値を他の列から伏せる。メールアドレスの形は全行で伏せる（最後の防御） |

あわせて、サーバの説明を書き直した。

```
個人情報が含まれていないと断定しないこと。
目印の位置から元のデータを推測して説明しないこと（目印は伏せた結果であり、事実ではない）。
```

修正後、Claude の説明は警告どおり「お名前の列に日時かメールアドレスが入っていた」になった。

**検査**：実データで漏れた形を、偽のシートに再現してテストにした（GAS 20件）。

```js
// お名前の列に日時が入っている行。日時欄は正しい
['2026/09/07 09:00:00', '2026/09/07 09:00:00', 'kato@example.com', '加藤です。…', 'システム障害', '高', ...]
// 期待：日時はそのまま、内容は [列ずれのため非表示]、[氏名] という目印は付かない
```

## 効かなかった対処

- **列で絞る**：列ずれで素通り
- **列ずれした行でも、同じ行の値で伏せる**：誤った目印を作った。**伏せることが、漏れとは別の種類の誤り（誤った情報）を作る**
- **正規表現を電話番号・住所まで広げる**：検討したが採らなかった。誤検知が増え、それ自体が誤った目印になる

**限界は残る。** 本文に書かれた**第三者の氏名**は形式で判定できず、伏せられない。

## 他人の環境に納品するときの含意

- **顧客のデータは必ず汚れている前提で、個人情報の扱いを設計する。** 列で絞るだけの設計を出さない
- **汚れた行の扱いを先に決める。** どこに何が入っているか分からない行は、推測で伏せずに**出さない**
- **伏せ字・目印は LLM にとって情報になる。** 誤った目印は、もっともらしい誤った説明の根拠になる
- **「含まれない」と宣言しない。** 保証できる範囲と限界を、ツールの説明に正直に書く
- **人が件数だけ見ていたら気づかなかった。** Claude がデータを読んで不自然さを指摘したから発覚した。
  納品前に、実データ（匿名化済み）で中身を目で見る工程を入れる
