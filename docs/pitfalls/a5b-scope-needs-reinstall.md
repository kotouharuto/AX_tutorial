# Slack アプリの権限：マニフェストに足しても再インストールするまで効かず、エラーも変わらない

- **ブロック：** A-5b
- **日付：** 2026-10-17
- **一般性：** どの環境でも（Slack アプリに権限を足すとき）
- **溶かした時間：** 未計測

## 現象

チャンネルへの通知のために `chat:write` を足していく過程で、エラーが次のように変わった。

| 段階 | 状態 | Slack のエラー |
|---|---|---|
| 1 | 権限は `commands` だけ | `missing_scope` |
| 2 | **マニフェストに `chat:write` を足して保存（再インストール前）** | **`missing_scope`**（`needed: chat:write:bot`／`provided: commands`） |
| 3 | 再インストール後 | `not_in_channel` |
| 4 | Bot を投稿先チャンネルに `/invite` | 成功 |

## 再現手順

1. `commands` だけの Bot で `chat.postMessage` を呼ぶ → `missing_scope`
2. 管理画面の App Manifest に `chat:write` を足して保存 → 同じ呼び出しは**同じ** `missing_scope`
3. 「Install App」から再インストール → `not_in_channel`
4. 投稿先で `/invite @bot名` → 成功

## 原因

- マニフェストは**「次にインストールするとき求める権限」の宣言**。保存しても、発行済みトークンの権限は変わらない。
  ワークスペースの側が新しい権限を許可する（再インストール）まで増えない
- 段階1と2のエラーが同じなので、**開発者には「足したのに直らない」としか見えない**
- エラーに出る権限名（`chat:write:bot`）と、マニフェストに書いて効いた名前（`chat:write`）が違う
- 権限が揃っても、Bot がメンバーでないチャンネルには投稿できない（`not_in_channel`）

## 対処

1. エラー応答の `needed`（必要な権限）と `provided`（トークンが今持つ権限）を**ログと運用チャンネルに出す**。
   `provided` に足した権限が無ければ再インストール前と分かる
2. 3段階（マニフェスト → 再インストール → `/invite`）を手順書に書く（`projects/a5b-slack-bot/HANDOVER.md` 4章）
3. 失敗通知に、エラーコードごとの直し方を付ける（`missing_scope` → 再インストール、`not_in_channel` → `/invite`）

再インストールしても Bot トークン（`xoxb-`）の文字列は変わらなかった（`.env` はそのままで効いた）。

## 効かなかった対処

- マニフェストに足して保存するだけ（段階2）
- エラーに出た `chat:write:bot` をそのままマニフェストに貼る発想（名前が一致しない。試してはいないが、名前の違いに気づかないとこれをやる）

## 他人の環境に納品するときの含意

- 権限を足す変更は「コードの変更」では終わらない。**顧客側のワークスペースで再インストールの承認が要る**ので、
  誰が承認できるかを事前に確認する（業務ワークスペースでは管理者の承認が要ることが多い）
- 新しい通知先チャンネルを作るたびに `/invite` が要る。運用担当の手順に入れる
