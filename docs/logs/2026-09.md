  「その他地域 12,000円」が何の経費区分か分からなくなる**

この確認を飛ばしていたら、評価そのものが成立しなかった。

### 気づき（効き幅）

- **前処理が支配的。** 全構成が Q12/Q17（画像PDF）を落とし、
  パラメータをどう変えても解決しない。パラメータの効き幅が最大4%（1問）なのに対し、
  前処理の欠落は8%（2問）を固定で失わせる。
- **1問=4% なので、+4% は誤差の範囲。**
  「埋め込みモデルの差は想像より小さい」という仮説は、
  この規模では**検証できなかった**（差が1問分しかない）。
- **Recall が同じでも落とす問題が入れ替わる。**
  baseline と overlap0 はどちらも88%だが、前者は Q16、後者は Q08 を落とす。
  「変わらなかった」と結論すると、**答えられる質問の集合が変わっていることを見逃す。**
- **top_k を5→10にしても改善しない。**
  上位5件に入らないものは10件でも入らない。取りこぼしの原因が
  「順位が足りない」ではなく「そもそも引っかかっていない」ことを示す。
- **短文コーパスでは効き幅が測れなかった。**
  1文書＝1チャンクだとチャンクサイズもオーバーラップも意味を持たない。
  長文版を別に作って測り直した（既製方式の再測定は不要だった。
  Recall 測定は自作RAG だけで完結するため）。

  A-4 は「自動で回すバッチ」なので、**壊れる側が実運用の経路**だった。
- **Windows 実機がないことは、検証の質の上限を決めなかった。** 実機を手で触るより、
  敵対的な環境変数を CI で強制する方が確実に見つかる。
  実際、実機の手動確認では見つからない不具合を実機なしで見つけた。
- **CI を緑にする修正と、不具合を直す修正は別物。** `PYTHONUTF8=1` を
  ワークフローに足せば緑になるが、環境変数は配布先に付いていかない。
  **前者をやって後者をやったつもりになる**のが危ない。
- **検証側のコードに同じ不具合があった。** 本体を直しても、CI に直書きした
  `python -c` のワンライナーは `console.py` を通らない。
  切り出した副産物として、欠損ファイルとサイズ0を異常として検出できるようになった
  （従来は一覧を印字するだけで成功扱い）。
- **スキャン待ちは遅延で済まないことがある。** xlsx 書き込み中に
  `TimeoutError: [Errno 60]` で異常終了し、再実行では9.6秒で成功した。
  **再現しない失敗**として現れるので、「もう一度やったら通った」で片付けると
  顧客環境で同じことが起きたときに説明できない。
- 自分の待機ループにバグを作った。`pgrep -f <名前>` は**待機ループ自身のコマンド文字列にマッチ**するため、
  対象が終了しても永久に回る。PID 指定の `kill -0` に直した。

  - [定期実行は対話シェルと別世界](../pitfalls/a5a-launchd-scheduled-execution.md)（214行）
- **完了条件の進み：** A-5a は 5/6
- **次回の入口：** 受注判断基準

### run.py の検証（6通り）

| 実行 | 状況 | 判定 | 終了コード |
|---|---|---|---|
| 1 | 初回 | 差分なし・通知しない | 0 |
| 2 | 変化なし | 差分なし・通知しない | 0 |
| 3 | 追加5件・変更1件 | 差分あり・通知 | 2 |
| 4 | セレクタ破壊（0件） | 異常・通知 | 1 |
| 5 | **件数正常・detail が全件空** | 異常・通知 | 1 |
| 6 | 復元 | 異常なし | 0 |

### 気づき

- **定期実行で3連続失敗した。** いずれも「対話シェルでは動くのに
  定期実行だけ壊れる」型。A-4 の cp1252 と同じ構造。
  1. `uv: command not found`（launchd は `~/.zshrc` を読まない）
  2. `Resource deadlock avoided`（**TCC が `~/Desktop` を拒否**）
  3. `bad interpreter`（venv ラッパーの shebang に旧絶対パス）
- **エラー文から原因が読めないときは、最小の再現を別に作る。**
  `Resource deadlock avoided` をいくら読んでも TCC には到達しない。
  `cat` と `ls` だけを実行する plist を作って `Operation not permitted` が出た。
- **`~/Desktop` は iCloud Drive の同期対象だった。** `mv` が CPU 0% で9分以上返らず、
  `fileproviderd` 114% / `bird` 48% を確認。**所要時間は約40分。**
  同期下は TCC 以前に置き場所として不適切（実体化、同期競合、オフライン失敗）。
  競合時に**エラーを出さず古いデータを読む**点は A-3 の SQLite WAL と同型。
- **置き場所で解決できるものを権限で解決しない。**
  フルディスクアクセスを付与すれば動くが、顧客に
  「バッチのために全ディスクアクセスを許可してください」とは言えない。
- **`.venv` についての自分の予想が外れた。** 移動しても `python` と
  パッケージ読み込みは動く（ベースはツリー外、site-packages は相対解決）。
  壊れるのはラッパーの shebang と `activate` だけ。**`uv sync` では直らない**
  （既存 venv を「監査済み」と判断して再生成しない）。
- **自分のミス：** `uv sync --extra dev` で `--extra js` を付け忘れ、
  **playwright が削除された。** uv sync は指定しなかった extra を消す。
- **差分検出は健全性の判定に使えない。** 壊れると差分が出なくなる。
  異常判定を別モジュールに分け、テストで「セレクタ破壊時に差分が出ない」ことを固定した。
- **通知の設計：** 差分なし・初回は通知しない（毎回メールが来ると読まれなくなる）。
  異常は必ず通知する。**沈黙を正常の合図にしない。**
